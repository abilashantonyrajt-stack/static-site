============================================================
HOW TO USE THIS BOOK
============================================================

This book explains the small website in the static site folder.
It starts with the basic ideas and then explains the real files.
Read one unit at a time. You do not need to know anything first.

Words used in this book:

HTML  - The structure of a web page. It tells the browser what exists.
CSS   - The design of a web page. It controls colors, sizes, and layout.
JavaScript - The behavior of a web page. It makes buttons do things.
Browser - A program such as Chrome that displays web pages.
Link   - Text or a button that takes you to another page.
Element - One piece of HTML, such as a heading or a button.
Attribute - Extra information inside an HTML opening tag.
Selector - A CSS pattern that chooses what should be styled.
Function - A named group of JavaScript instructions.
Path   - The address that tells the browser where a file is.

The project is called a static site because it is made from files that
are sent directly to the browser. It does not currently have a real
server database or working login system.

CHAPTER 1 - WHAT A WEBSITE IS
------------------------------

A website is a group of files that work together.

HTML gives the page its skeleton. For example, HTML can create:
- a heading
- a paragraph
- a picture
- a link
- a form

CSS gives the skeleton its appearance. CSS can change:
- color
- size
- space
- position
- background
- mobile layout

JavaScript gives the page actions. JavaScript can:
- open a dropdown
- close a dropdown
- search for a service
- check a form
- change the page

A simple way to remember this is:

HTML = what is on the page
CSS = how it looks
JavaScript = what it does

Your beauty website uses all three.

CHAPTER 3 - HOW A BROWSER READS FILES
------------------------------

When you open index.html, the browser starts at the top.

1. It reads the HTML.
2. It finds the CSS link and loads style.css.
3. It builds the page structure.
4. It finds the JavaScript link and loads index.js.
5. It displays the page.
6. When you click a button, JavaScript may respond.

A path beginning with ./ means "start in the current folder."
For example, in index.html:

./style.css

means style.css is beside index.html.

A path beginning with ../ means "go up one folder."
Two ../ parts mean go up two folders.
In HairStyling.html:

../../style.css

means:
- start in navigation/menu
- go up to navigation
- go up to front-end
- find style.css

A wrong path means the browser cannot find the file.

------------------------------
CHAPTER 4 - THE BASIC HTML PAGE
------------------------------

A complete HTML page normally looks like this:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Page title</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h1>Page heading</h1>
  <p>Page text.</p>
</body>
</html>

Line explanation:

<!DOCTYPE html>
This tells the browser to use modern HTML rules.
It is a declaration, not normal page content.

<html lang="en">
This starts the HTML document. The lang attribute says the page uses
English. This helps browsers and screen readers.

<head>
This starts the hidden information area. The head is not normally shown
as page content.

<meta charset="UTF-8">
This tells the browser how to read letters and symbols.

<meta name="viewport" content="width=device-width, initial-scale=1.0">
This helps the page fit phones and tablets.

<title>Page title</title>
This sets the text shown in the browser tab.

<link rel="stylesheet" href="style.css">
This connects the HTML page to a CSS file.

</head>
This ends the hidden information area.

<body>
This starts the visible page content.

<h1>Page heading</h1>
This creates the main heading. A page normally has one main h1.

<p>Page text.</p>
This creates a paragraph.

</body>
This ends the visible content.

</html>
This ends the document.

HTML tags usually have an opening tag and a closing tag.
For example:

<p>Text</p>

The first p opens a paragraph. The second p, with a slash, closes it.
Some elements, such as input and meta, do not need a closing tag.

------------------------------
CHAPTER 5 - TEXT, LINKS, BUTTONS, AND FORMS
------------------------------

A link uses the a element:

<a href="login.html">Book Now</a>

The href attribute gives the destination.
The words between the tags are what the visitor clicks.

A button uses the button element:

<button type="button">Click me</button>

A button can run JavaScript:

<button onclick="find()">Search</button>

The onclick attribute says to call find when the button is clicked.

A form collects information:

<form action="/login" method="post">
  <label for="username">Username</label>
  <input id="username" name="username" type="text">
  <button type="submit">Login</button>
</form>

The form element holds the fields.
The action says where the information should be sent.
The method says how it should be sent.
The label describes a field.
The for value should match the field id.
The input is where the visitor types.
The name is the name sent with the form.
The submit button sends the form.

The current project has forms, but no real backend endpoint.
Therefore the forms are visual demonstrations and are not a complete
login or contact system yet.

------------------------------
CHAPTER 6 - FILE PATHS AND CAPITALIZATION
------------------------------

A link is only useful if its path matches a real file.
For example, the home page uses:

./navigation/menu/HairStyling.html

This points to the HairStyling.html file inside navigation/menu.

A path problem from the older code was:

./navigation/About_us.html

The real file is named About_Us.HTML.
The word Us has a capital U, and the extension has capital letters.
The path should match the real file exactly:

./navigation/About_Us.HTML

Another older problem was:

./navigation/wish_list.html

The real file is Wish_list.HTML.
Again, the capitalization and extension are different.

Another problem was in the profile fragment:

./navigation/Profile/Picture.html

The real folder is profile with a lowercase p. The real file is also
picture.html with a lowercase p. A path should use the real folder.

A useful beginner habit is:
1. Look at the folder.
2. Copy the exact file name.
3. Paste it into href.
4. Check every capital letter.

------------------------------
CHAPTER 10 - RESPONSIVE DESIGN
------------------------------

Responsive design means one page can work on a large monitor and a phone.

A desktop has room for Menu, Profile, and a search input in rows.
A phone has less room, so flex items are allowed to wrap or stack.

The project uses:
- flex layouts
- grid layouts
- min and max widths
- a media query
- flexible hero text

The CSS uses clamp for the hero heading:

font-size: clamp(3rem, 8vw, 6.5rem);

This means:
- never smaller than 3rem
- try a size based on 8 percent of the viewport width
- never larger than 6.5rem

------------------------------
CHAPTER 11 - READING index.js LINE BY LINE
------------------------------

The current file is front-end/index.js.

function toggleDropdown(dropdownId) {
This starts a function named toggleDropdown.
The function receives a value called dropdownId.
A value inside the parentheses is called a parameter.

const dropdown = document.getElementById(dropdownId);
The browser document is searched for the element with that ID.
const creates a variable that should not be reassigned.

const isOpen = dropdown.style.display === "block";
This checks whether the menu's inline display value is block.
The result is true or false.
The three equal signs compare values strictly.

 document.querySelectorAll(".dropdown-content").forEach((menu) => {
This finds every dropdown-content element and repeats the next action
for each one.
The arrow function receives one menu at a time.

menu.style.display = "none";
Every dropdown is first hidden. This closes another open dropdown.

});
This ends the repeated action.

dropdown.style.display = isOpen ? "none" : "block";
This is a short if statement called a ternary expression.
If isOpen is true, use none. Otherwise use block.
This opens the selected menu or closes it if it was already open.

}
This ends toggleDropdown.

window.addEventListener("click", (event) => {
This listens for every click on the window.
The event object describes the click.

if (!event.target.closest(".dropdown")) {
The code asks whether the clicked element is inside a dropdown.
If it is not inside one, the following code runs.

 document.querySelectorAll(".dropdown-content").forEach((menu) => {
Again, find all dropdown menus and repeat an action.

menu.style.display = "none";
Hide every menu. This closes open menus when the visitor clicks elsewhere.

});
}
});
These braces end the if, the event function, and the event listener.

function find() {
This starts the search function. The Search button calls it.

const query = document.getElementById("searchInput").value.toLowerCase();
Find the search box, read its value, and change it to lowercase.
This means Hair and hair can be treated the same way.

// Perform search logic here
This is a comment. The browser ignores it.
It explains that search logic follows.

if (query.includes("hair")) {
If the typed words contain hair, the first result is used.
includes returns true or false.

window.location.href = "./navigation/Menu/HairStyling.html";
Change the browser address to the Hair Styling page.
window.location is the current page location.
href is its address.

} else if (query.includes("treatment")) {
If hair was not found, check for treatment.

window.location.href = "./navigation/Menu/HairTreatment.html";
Open the Hair Treatment page when treatment is found.

} else {
If neither word was found, use the final choice.

alert("result not found for: " + query);
Show a browser alert with the typed search words.
The plus sign joins strings together.

}
}
These braces close the search choices and the function.

------------------------------
CHAPTER 12 - DROPDOWN BEHAVIOR AND SEARCH
------------------------------

The menu button sends menuDropdown to the function.
The profile button sends profileDropdown.
Because the IDs are different, JavaScript opens the correct list.

The old code had two functions that both searched for:

 document.getElementById("myDropdown")

Both menu and profile fragments used the same ID.
That caused the wrong dropdown to be selected when both existed together.
The old code also assigned window.onclick twice. The second assignment
replaced the first one.

The new code has one function and one click listener.
This is easier to read and less likely to conflict.

The search is deliberately simple. It only knows the words hair and
treatment. It does not search every service yet.

UNIT 7 - PROBLEMS, FIXES, AND NEXT LESSONS
============================================================

------------------------------
CHAPTER 17 - WHAT WAS WRONG OR MISPLACED
------------------------------

Problem 1: The menu and profile were inside object elements.
An object creates an embedded document. The old CSS gave the object a
very small height. Dropdown content opened inside that small area and
could be clipped.

Problem 2: Both old dropdowns used id="myDropdown".
IDs should be unique on one page. JavaScript could find only the first
matching element reliably.

Problem 3: The old JavaScript had two window.onclick assignments.
The second assignment replaced the first assignment. This made the code
hard to reason about and could remove earlier behavior.

Problem 4: The old JavaScript had two separate functions, toggleMenu and
toggleProfile, but both searched for the same ID.
The function names looked different, but their target was not different.

Problem 5: CSS was placed inside HTML.
The old index.html, Menu.HTML, and Profile.HTML contained style blocks.
This made design rules difficult to find and repeat.

Problem 6: Some old links did not match real file names.
About_us.html did not exactly match About_Us.HTML.
Wish_list.html did not exactly match Wish_list.HTML.
Some profile paths used Profile with a capital P even though the folder is
profile with a lowercase p.

Problem 7: The menu listed Makeup.html, but Makeup.html does not exist.
That link is unfinished.

Problem 8: Many files are only fragments.
A fragment can be useful inside another page, but a visitor opening it
directly should receive a complete HTML document.

Problem 9: Several profile pages are empty.
Their links work as paths, but their pages have no visible content.

Problem 10: The login and contact forms have no backend.
The browser can display and validate basic fields, but no server code
currently receives or stores the information.

Problem 11: Search only handles two words.
The find function recognizes hair and treatment, but not manicure,
pedicure, or other services.

Problem 12: The image is not currently used on HairStyling.
hairstyle1.png exists, but there is no img element in the current hero.

Problem 13: The home page once had unnecessary inline positioning.
The old search button was pushed down and sideways with top and left.
This is fragile. The current flex search row is easier to control.

FINAL QUICK REFERENCE
============================================================

When you want to change content:
Open the matching .html file.

When you want to change colors, spacing, fonts, or layout:
Open front-end/style.css.

When you want to change clicks, dropdowns, or search:
Open front-end/index.js.

When a link fails:
Check the folder, filename, capitalization, and extension.

When a dropdown is clipped:
Check whether it is trapped inside an iframe or object with a small height.

When two controls behave strangely:
Check whether they share an ID or whether an event handler is being
replaced by another handler.

When a form looks correct but does not save anything:
Remember that HTML forms need a backend server to process their data.

The most important rule for this project is:

Keep structure in HTML, design in CSS, and behavior in JavaScript.
